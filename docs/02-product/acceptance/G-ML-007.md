## 🏛️ Executive Summary

This acceptance contract defines the formal verification and empirical assurance criteria for Goal G-ML-007: Parameter-Efficient LoRA/QLoRA Training Pipeline. Soda OS establishes an end-to-end parameter-efficient training pipeline orchestrator (`Trainer` in `code/ml/src/training/train_pipeline.py`) that attaches LoRA adapters to attention projection layers and simultaneously optimizes the auxiliary confidence/value projection head under a composite joint loss combining language preservation and calibrated RLCD reward. Base transformer backbone parameters remain strictly frozen, limiting trainable parameters to under 2% of the model parameter count, and checkpoints are persisted in standard safetensors format.

## 🧪 BDD Given-When-Then Acceptance Scenarios

### Scenario 1: AC-ML-007-01: Parameter Freezing and LoRA Trainable Parameter Bound (< 2%)
```gherkin
Feature: Parameter Freezing and LoRA Trainable Parameter Bound
  Scenario: Base model backbone parameters remain frozen while LoRA and value head are trainable
    Given a DualHeadCausalLM model with base transformer backbone and auxiliary confidence head
    When LoRA adapter is injected via PEFT targeting attention projections
    And parameter freezing is applied to the base transformer backbone
    Then the total trainable parameters count constitutes strictly less than 2.0% of total parameters
    And all base transformer parameters have requires_grad set to False
    And all LoRA adapter weights and confidence head parameters have requires_grad set to True.
```

### Scenario 2: AC-ML-007-02: Joint Language Preservation and Calibrated Reward Loss Optimization
```gherkin
Feature: Joint Objective Computation
  Scenario: Training step calculates composite loss summing language preservation and calibrated reward
    Given a training batch with input token IDs, completion labels, target correctness outcomes, and optional evidence verification
    When the Trainer executes forward loss computation
    Then the computed total loss equals the sum of LanguagePreservationLoss and gamma-scaled CalibratedRewardLoss
    And all intermediate loss components (nll_loss, kl_loss, proper_loss, overconfidence_penalty, brier_loss, evidence_penalty) are logged
    And zero NaN or Infinity values are emitted.
```

### Scenario 3: AC-ML-007-03: Mini-batch Training Step and Weight Updates
```gherkin
Feature: Mini-batch Training Step and Weight Updates
  Scenario: Executing optimization steps updates adapter and value head tensor weights
    Given a Trainer initialized with DualHeadCausalLM, LoRA adapters, optimizer, and training dataset
    When 3 consecutive training mini-batches are executed through forward, backward, and optimizer step
    Then the optimizer step completes cleanly with exit code 0
    And the parameter weights of the LoRA adapters and confidence head change from their initial state
    And the base backbone weights remain identical to their initial state.
```

### Scenario 4: AC-ML-007-04: Standalone Adapter and Value Head Safetensors Checkpointing
```gherkin
Feature: Safetensors Checkpoint Emission
  Scenario: Saving checkpoint persists adapter weights and value head in valid safetensors format
    Given a trained model after optimization steps
    When the Trainer invokes save_checkpoint to a target output directory
    Then an adapter_model.safetensors and value_head.safetensors (or unified model.safetensors) file is emitted
    And the checkpoint can be reloaded and verified using safetensors.torch.load_file
    And the reloaded tensor weights match the in-memory parameter tensors exactly.
```

### Scenario 5: AC-ML-007-05: Fail-Closed Numerical Stability and Non-Finite Gradient Rejection
```gherkin
Feature: Fail-Closed Numerical Stability
  Scenario: Non-finite loss or gradients immediately trigger fail-closed abortion
    Given corrupted input tensors or divergent activations producing NaN or Inf
    When forward or backward execution is performed
    Then the Trainer catches the non-finite condition and raises a fatal ValueError or FloatingPointError
    And partial corrupt updates are not committed to model weights.
```
