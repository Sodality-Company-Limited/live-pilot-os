## 🏛️ Executive Summary

This acceptance contract defines the formal verification and empirical assurance criteria for Goal G-ML-008: Verification and Defer-Policy Optimization. Soda OS establishes a decision policy optimization module (`DeferPolicyOptimizer` and `DecisionRouter` in `code/ml/src/training/defer_policy.py`) that tunes dual-threshold boundaries ($\tau_{\text{low}}, \tau_{\text{high}}$) to map continuous confidence estimates and context into discrete action policies (`proceed`, `verify`, `defer`, `human_review`). The module enforces an asymmetric risk matrix that penalizes false acceptances at least 10x higher than false deferrals, bounds false acceptances below 1.0% and false deferrals below 5.0%, routes 100% of high-risk decisions with confidence below 0.85 to `defer` or `verify`, and serializes calibrated configurations to `code/ml/configs/policy_thresholds.yaml`.

## 🧪 BDD Given-When-Then Acceptance Scenarios

### Scenario 1: AC-ML-008-01: High-Risk Decision Deferral and Verification Enclosure (< 0.85)
```gherkin
Feature: High-Risk Decision Routing Guard
  Scenario: All high-risk decisions with confidence below 0.85 are routed to defer or verify
    Given a batch of decision instances flagged with risk_level "high" and confidence c < 0.85
    When evaluated by DecisionRouter using calibrated thresholds
    Then exactly 100% of the decisions are routed to "defer" or "verify"
    And zero decisions are routed to "proceed".
```

### Scenario 2: AC-ML-008-02: False Deferral Rate Bounded Below 5%
```gherkin
Feature: Bounded False Deferral Rate
  Scenario: False deferrals on correct, verified normal-risk decisions remain strictly below 5%
    Given a validation split of correct normal-risk predictions with verified evidence and high confidence
    When the DeferPolicyOptimizer tunes thresholds tau_low and tau_high
    Then the resulting empirical false deferral rate is strictly less than 5.0%
    And the optimized thresholds satisfy 0.0 <= tau_low < tau_high <= 1.0.
```

### Scenario 3: AC-ML-008-03: Asymmetric Empirical Risk Minimization
```gherkin
Feature: Risk-Weighted Cost Matrix
  Scenario: Cost function penalizes confident incorrect decisions 10x higher than deferrals
    Given a CostMatrix configured with false acceptance cost C_fa = 10.0 and false deferral cost C_fd = 1.0
    When evaluating expected risk over incorrect assertions versus deferred decisions
    Then the unit penalty for false acceptance is exactly 10.0 times the unit cost of false deferral
    And the computed empirical loss is strictly non-negative.
```

### Scenario 4: AC-ML-008-04: Canonical Routing Token Conformance and Truth Table Execution
```gherkin
Feature: Routing Token and Truth Table Conformance
  Scenario: Decision routing strictly matches the canonical 8-case truth table
    Given decisions spanning all combinations of risk (normal, high), evidence (verified, unverified), and confidence (high, low)
    When evaluated by the DecisionRouter
    Then each output belongs strictly to ActionPolicy (proceed, verify, defer, human_review)
    And matches the exact expected action defined in G-ML-008 routing_contract.
```

### Scenario 5: AC-ML-008-05: Fail-Closed Input Validation and Degenerate Boundary Handling
```gherkin
Feature: Fail-Closed Input Validation
  Scenario: Invalid confidence scores, corrupt risk tags, or inverted thresholds raise ValueError
    Given input with confidence outside [0.0, 1.0], NaN, Inf, invalid risk strings, or tau_low >= tau_high
    When submitted to DecisionRouter or DeferPolicyOptimizer
    Then a ValueError is raised immediately
    And no unverified action policy is returned.
```
