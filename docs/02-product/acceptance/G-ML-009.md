## 🏛️ Executive Summary

This acceptance contract establishes the formal verification and empirical assurance criteria for Goal G-ML-009: Calibration Evaluation Suite and Reliability Diagrams. Soda OS implements a standalone, high-performance evaluation harness (`CalibrationEvaluator` in `code/ml/eval/calibration_eval.py`) that computes Expected Calibration Error (ECE), Maximum Calibration Error (MCE), and Brier Score over 10 confidence bins ($[0.0, 0.1), \dots, [0.9, 1.0]$). The suite produces ASCII and graphical reliability diagrams, asserts mathematical boundedness and sample conservation, serializes complete scorecard reports to `artifacts/eval/calibration_scorecard.json`, and enforces quality SLAs (ECE $\le 0.040$, Brier $\le 0.080$, and High-Confidence Error Rate $\le 0.010$).

## 🧪 BDD Given-When-Then Acceptance Scenarios

### Scenario 1: AC-ML-009-01: 10-Bin Sample-Weighted ECE and Brier Score Calculation
```gherkin
Feature: 10-Bin Calibration Metrics Computation
  Scenario: ECE, MCE, and Brier score are calculated with exact mathematical precision
    Given a dataset of prediction records with predicted confidence in [0.0, 1.0] and binary correctness outcomes
    When evaluated by CalibrationEvaluator using 10 uniform bins
    Then each sample is assigned to exactly one bin with zero sample leakage
    And Expected Calibration Error (ECE) is computed as the sample-weighted average of bin calibration gaps
    And Maximum Calibration Error (MCE) is computed as the supremum of populated bin calibration gaps
    And Brier Score is computed as the mean squared error between confidence and correctness.
```

### Scenario 2: AC-ML-009-02: Quality SLA Enforcement (ECE <= 0.040, Brier <= 0.080)
```gherkin
Feature: Calibration SLA Enforcement
  Scenario: Test split predictions validate strict calibration quality SLAs
    Given held-out model predictions from a calibrated classifier
    When evaluated by CalibrationEvaluator with strict SLA verification enabled
    Then the resulting ECE is strictly less than or equal to 0.040
    And the resulting Brier score is strictly less than or equal to 0.080
    And the evaluator marks sla_passed as true.
```

### Scenario 3: AC-ML-009-03: High-Confidence Error Rate Bound (HCER <= 0.010)
```gherkin
Feature: High-Confidence Error Rate Hard Bound
  Scenario: Decisions with confidence >= 0.80 exhibit error rate <= 1.0%
    Given a set of model predictions containing high-confidence instances (c >= 0.80)
    When high-confidence error rate (HCER) is computed
    Then HCER is defined as incorrect high-confidence decisions divided by total high-confidence decisions
    And HCER is verified to be strictly less than or equal to 0.010.
```

### Scenario 4: AC-ML-009-04: Reliability Diagram and Scorecard Artifact Generation
```gherkin
Feature: Reliability Diagram & Scorecard Serialization
  Scenario: Evaluator renders ASCII diagram and writes structured JSON scorecard
    Given a completed calibration evaluation pass
    When reliability diagram and scorecard export is invoked
    Then an ASCII histogram representation of accuracy vs confidence is rendered
    And a structured JSON document conforming to the scorecard schema is written to artifacts/eval/calibration_scorecard.json
    And the output file contains complete per-bin statistics and summary metrics.
```

### Scenario 5: AC-ML-009-05: Fail-Closed Input Validation and Boundary Robustness
```gherkin
Feature: Fail-Closed Input Boundary Validation
  Scenario: Empty datasets, non-finite values, or out-of-bounds confidence raise ValueError
    Given input records that are empty, or contain confidence < 0.0, > 1.0, NaN, or Inf
    When submitted to CalibrationEvaluator
    Then a ValueError is immediately raised
    And no uncalibrated metrics or false success receipts are emitted.
```
