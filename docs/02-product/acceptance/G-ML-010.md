## 🏛️ Executive Summary

This acceptance contract establishes the formal verification and empirical assurance criteria for Goal G-ML-010: Text-Generation Regression and Linguistic Quality Suite. Soda OS implements a standalone, high-performance regression evaluation harness (`TextRegressionEvaluator` in `code/ml/eval/text_regression_eval.py`) that evaluates the dual-head trained model against the reference base checkpoint across coding, reasoning, and instruction-following benchmarks. The suite measures comparative token perplexity, enforces that perplexity degradation is bounded below 3.0%, executes native AST syntax validation ensuring code syntax validity $\ge 98.0\%$, asserts autoregressive generation length consistency, serializes complete scorecard reports to `artifacts/eval/text_regression_scorecard.json`, and enforces strict quality gates with zero mocks and zero stubs.

## 🧪 BDD Given-When-Then Acceptance Scenarios

### Scenario 1: AC-ML-010-01: Comparative Perplexity Measurement (< 3.0% Degradation)
```gherkin
Feature: Comparative Perplexity Regression Gate
  Scenario: Perplexity increase on held-out reference text is bounded strictly below 3.0%
    Given a reference base model and a fine-tuned dual-head model
    And a set of held-out reasoning and coding benchmark evaluation prompts
    When TextRegressionEvaluator computes the cross-entropy perplexity for both models
    Then the perplexity degradation percentage (PPL_dual - PPL_base) / PPL_base * 100% is computed
    And the degradation is verified to be strictly less than 3.0%
    And perplexity_gate_passed is set to true.
```

### Scenario 2: AC-ML-010-02: Native AST Syntax Validity Verification (>= 98.0%)
```gherkin
Feature: Code Syntax Validity and AST Parsing
  Scenario: Generated code samples achieve >= 98.0% grammatical validity
    Given a battery of code generation benchmark prompts across Python, JavaScript, and Rust
    When completions are generated by the model
    And code blocks are extracted and parsed by native AST verifiers
    Then each snippet is categorized as valid or invalid without crashing
    And the aggregate syntax validity rate is verified to be greater than or equal to 98.0%
    And syntax_gate_passed is set to true.
```

### Scenario 3: AC-ML-010-03: Autoregressive Generation Invariants & Length Preservation
```gherkin
Feature: Autoregressive Generation Invariance
  Scenario: Autoregressive generation length and repetition penalty match base model behavior
    Given identical greedy decoding parameters and prompt prefixes
    When text generation is executed on the dual-head model and base model
    Then the average generation length ratio L_dual / L_base is within [0.95, 1.05]
    And n-gram repetition rates remain strictly within +/- 2.0% of the baseline.
```

### Scenario 4: AC-ML-010-04: Regression Scorecard Serialization
```gherkin
Feature: Regression Scorecard JSON Ledger Persistence
  Scenario: Evaluator exports structured scorecard to artifacts/eval/text_regression_scorecard.json
    Given a completed text regression evaluation pass
    When export_scorecard is invoked
    Then a structured JSON document conforming to TextRegressionScorecard schema is written
    And the scorecard records base perplexity, dual-head perplexity, delta percent, syntax validity rate, and gate statuses
    And the file includes exact-HEAD git provenance and ISO 8601 UTC timestamp.
```

### Scenario 5: AC-ML-010-05: Fail-Closed Input Validation & Quality Gate Enforcement
```gherkin
Feature: Fail-Closed Boundary Robustness
  Scenario: Empty prompts or SLA quality breach raises TextRegressionGateError
    Given invalid input states such as empty prompt lists, non-finite loss tensors, or uncalibrated degradation exceeding 3.0%
    When evaluated with strict SLA enforcement enabled
    Then a fail-closed exception (ValueError or TextRegressionGateError) is immediately raised
    And no false success receipts or unverified scorecards are emitted.
```
