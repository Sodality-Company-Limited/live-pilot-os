# Acceptance Contract: G-ML-021

**Goal:** G-ML-021: Model Regression and Integration Test Harness  
**Epic:** ML  
**Version:** 1.0.0  
**Status:** active  

---

## 1. Feature Definition

```gherkin
Feature: Model Regression and Integration Test Harness
  As a Soda OS Autonomous Agent and Quality Assurance Engineer
  I want an end-to-end integration test harness executing multi-step agent workflows against the calibrated model runtime
  So that tool calling, dynamic routing, decision ledger audit logging, and missing evidence recovery operate harmoniously with zero unhandled exceptions.
```

---

## 2. BDD Given-When-Then Scenarios

### Scenario 1: Dry-Run CLI Initialization Contract
```gherkin
Scenario: Agent Workflow Harness Dry-Run Execution Exits 0
  Given the AgentWorkflowHarness class and CLI entry point in `scripts/harness/agent-workflow-harness.mjs`
  When `node scripts/harness/agent-workflow-harness.mjs --dry-run` is invoked
  Then the process MUST exit cleanly with code 0
  And stdout MUST report that the harness initialized and executed dry-run scenarios cleanly.
```

### Scenario 2: End-to-End Goal Creation and Multi-Step Tool Calling Workflow
```gherkin
Scenario: Multi-Step Goal Execution with Calibrated Model and Verified Evidence
  Given an agent workflow task requiring goal initialization, inference dispatch, and file evidence verification
  When the agent workflow executes with valid evidence citations and calibrated model confidence >= 0.80
  Then the decision router MUST assign action `proceed`
  And the decision ledger MUST append an immutable audit record with verified citations and SHA256 digest
  And the step MUST complete without uncaught exceptions.
```

### Scenario 3: Missing Evidence Recovery Route Handling
```gherkin
Scenario: Routing to Verify on Missing Evidence and Recovery Query Emission
  Given an agent workflow step where cited evidence files are absent on disk
  When `node tests/e2e/test-calibrated-agent-workflow.mjs -k test_missing_evidence` is executed
  Then the decision router MUST assign action `verify` instead of `proceed`
  And a recovery query MUST be generated and logged to the decision ledger
  And the test MUST pass with exit code 0.
```

### Scenario 4: High-Risk Action Guardrails (Human Review & Deferral)
```gherkin
Scenario: High-Risk Action Routing Isolation
  Given a high-risk agent workflow operation (e.g. destructive modification or financial transfer)
  When the model returns high confidence (>= 0.80) with verified evidence
  Then the decision router MUST assign action `human_review`
  When the model returns low confidence (< 0.80) or unverified evidence
  Then the decision router MUST assign action `defer`
  And under NO circumstances may high-risk unverified actions route to `proceed`.
```

### Scenario 5: Full 5-Scenario Integration Battery Verification
```gherkin
Scenario: Complete Multi-Step Agent Loop Execution Over 5 Scenarios
  Given the full suite of 5 distinct operational agent scenarios:
    1. Standard goal specification and verification (proceed)
    2. Missing evidence recovery loop (verify -> recovered -> proceed)
    3. Low confidence decision deferral (verify / defer)
    4. High-risk tool invocation gating (human_review)
    5. Corrupt / invalid input fail-closed rejection (reject)
  When `node scripts/harness/agent-workflow-harness.mjs` is executed
  Then all 5 scenarios MUST pass with 100% green assertions
  And the process MUST exit with code 0 with zero unhandled promise rejections.
```

### Scenario 6: CLI Help Flag Contract
```gherkin
Scenario: Display CLI Options on --help
  When `node scripts/harness/agent-workflow-harness.mjs --help` is invoked
  Then the output MUST display usage flags (`--dry-run`, `--scenario`, `--verbose`, `--help`)
  And the process MUST exit with code 0.
```
