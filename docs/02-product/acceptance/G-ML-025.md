# Acceptance Contract: G-ML-025

**Goal:** G-ML-025: DAVE Decision Trajectory and Correction Dataset  
**Epic:** ML  
**Version:** 1.0.0  
**Status:** active  

---

## 1. Feature Definition

```gherkin
Feature: DAVE Decision Trajectory and Correction Dataset Ingestion Pipeline
  As a Machine Learning Engineer and Autonomous Agent Platform Operator
  I want a stream-processing trajectory ingestion and normalization pipeline transforming operational DAVE decisions, human review corrections, and empirical harness outcomes into structured RLCD preference pairs
  So that fine-tuning models for calibrated decision-making are trained on verified ground-truth preference pairs with strictly enforced split isolation and zero sample contamination.
```

---

## 2. BDD Given-When-Then Scenarios

### Scenario 1: Operational Decision Ingestion and Trajectory Normalization
```gherkin
Scenario: Ingestion pipeline extracts audit logs and normalizes context without dropped attributes
  Given an append-only JSONL audit ledger at `.agents/audit/decisions.jsonl`
  When `ingestDecisionTrajectories` processes the stream
  Then all decision records MUST be parsed with preserved `goal_id`, `decision_id`, `confidence`, `evidence`, `references`, and `decision` payload
  And any record lacking a `goal_id` correlation key MUST be rejected fail-closed
  And `normalizeDecisionPrompt` MUST output a canonical structured representation with explicit sections for Task, Domain, Risk, Summary, Evidence, References, Assumptions, and Verification Gates.
```

### Scenario 2: Correction Category Mapper and Authoritative Objective Label Oracle
```gherkin
Scenario: Objective harness pass/fail outcomes determine authoritative ground truth labels
  Given an ingested operational decision trajectory with empirical outcomes and human actions
  When `mapCorrectionAndOracleLabel` evaluates the decision
  Then an empirical harness passing outcome MUST be designated authoritative ground truth (`isCorrect: true`)
  And a test failure or human rejection MUST be designated authoritative ground truth failure (`isCorrect: false`)
  And human corrections MUST be mapped to canonical categories (`syntax_conformance`, `architectural_invariant`, `visual_fidelity_boundary`, `accessibility_contrast`, `security_isolation`, `confidence_calibration`)
  And `generatePreferencePairs` MUST assign the corrected proposal as `chosen` and the flawed proposal as `rejected`.
```

### Scenario 3: Calibrated Reward Scoring with Asymmetric 10x Penalty
```gherkin
Scenario: Reward engine scores calibrated logarithmic utility and penalizes overconfident errors
  Given a candidate decision with reported confidence $c \in [0.0, 1.0]$ and ground truth correctness $y \in \{0, 1\}$
  When `calculateCalibratedReward` computes the reward
  Then logarithmic utility MUST follow $R_{\text{log}} = y \cdot \ln(c) + (1-y) \cdot \ln(1-c)$
  And when $y = 0$ and $c \ge 0.80$, an asymmetric penalty of $c^2 \times 10.0$ MUST be deducted from net reward
  And correct high-confidence decisions MUST incur zero overconfidence penalty.
```

### Scenario 4: Train/Validation/Test Split Isolation and Zero Contamination
```gherkin
Scenario: Dataset partitioner enforces 80/10/10 split with zero sample leakage
  Given an array of generated RLCD preference pairs
  When `partitionDatasetSplits` is executed with 80% train, 10% validation, and 10% test ratios
  Then the set intersection of trajectory IDs between train, validation, and test MUST be strictly empty
  And the set intersection of prompts between train and test MUST be strictly empty
  And each record MUST contain an immutable `split` attribution tag.
```

### Scenario 5: Schema Validation Gatekeeper and Automated Test Pass
```gherkin
Scenario: Training contract harness validates RLCD preference dataset schema
  Given the exported RLCD dataset at `artifacts/rlcd/train_dataset.jsonl`
  When inspected via `node scripts/harness/model-training-contract-harness.mjs`
  Then every preference pair MUST satisfy the canonical schema (`trajectory_id`, `prompt`, `chosen`, `rejected`, `confidence`, `reward`, `split`)
  And the command MUST exit code 0 with zero schema or split contamination errors.
```
