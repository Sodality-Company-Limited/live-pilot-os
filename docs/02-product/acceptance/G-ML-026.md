# Acceptance Contract: G-ML-026

**Goal:** G-ML-026: DAVE RLCD Confidence-Calibrated Training Pipeline  
**Epic:** ML  
**Version:** 1.0.0  
**Status:** active  

---

## 1. Feature Definition

```gherkin
Feature: DAVE RLCD Confidence-Calibrated Training Pipeline
  As a Machine Learning Engineer and Autonomous Platform Operator
  I want a reinforcement learning from cognitive decision feedback (RLCD) training loop optimizing autoregressive language modeling alongside asymmetric confidence calibration penalties
  So that fine-tuned decision models express calibrated uncertainty, penalize confident false acceptances 10x more heavily than uncertain errors, and satisfy overconfidence safety gates.
```

---

## 2. BDD Given-When-Then Scenarios

### Scenario 1: Composite Loss Function with Strictly Proper Logarithmic Scoring
```gherkin
Scenario: Composite loss calculates exact logarithmic utility and penalizes confident errors 10x
  Given a decision candidate with reported confidence $c \in [0.0, 1.0]$ and ground truth correctness $y \in \{0, 1\}$
  When `computeCompositeRlcdLoss` computes the objective $L = L_{LM} + \lambda_c L_{cal} + \lambda_e L_{evidence} + \lambda_s L_{safety}$
  Then proper logarithmic loss MUST follow $L_{\text{log}} = -(y \ln c + (1-y) \ln(1-c))$ with $\epsilon = 10^{-6}$ clamping
  And when $y = 0$ and $c \ge 0.80$, an asymmetric penalty of $c^2 \times 10.0$ MUST be added to calibration loss
  And any negative loss output or NaN MUST halt execution fail-closed with descriptive errors.
```

### Scenario 2: Parameter-Efficient LoRA Adapter Initialization and Forward Pass
```gherkin
Scenario: LoRA adapter initializes with rank 16 and alpha 32 with zero initial delta
  Given a LoRA adapter configured with rank 16, alpha 32, and target modules `q_proj`, `v_proj`, and `value_head`
  When `DaveLoraAdapter` is instantiated
  Then all $B$ matrices MUST be initialized to exact zero ($B = 0$) such that $\Delta W = 0$
  And the forward pass MUST output valid autoregressive token logits and bounded confidence $\hat{c} \in [0.0, 1.0]$.
```

### Scenario 3: Training Epoch Execution and Gradient Stability
```gherkin
Scenario: Training epoch executes across batches with declining loss and stable gradient norms
  Given a training dataset of preference trajectories at `artifacts/rlcd/train.jsonl`
  When `DaveRlcdTrainer.trainAllEpochs` executes across 5 epochs
  Then mean training loss MUST exhibit a declining trajectory ($L_{\text{final}} \le L_{\text{initial}}$)
  And all gradient norms MUST remain strictly below the $10.0$ stability ceiling ($\|\nabla \theta\|_2 \le 10.0$).
```

### Scenario 4: Checkpoint Calibration Evaluation and Overconfidence Safety Gate
```gherkin
Scenario: Checkpoint evaluation computes calibration metrics and enforces safety gate
  Given a trained model checkpoint evaluated on `artifacts/rlcd/validation.jsonl`
  When `evaluateCheckpointCalibration` computes ECE, Brier score, accuracy, and HCER
  And `verifyOverconfidenceSafetyGate` compares metrics against baseline
  Then checkpoint ECE MUST be less than or equal to baseline ECE ($ECE \le \text{baseline\_ECE}$)
  And task accuracy MUST be preserved within 0.02 of baseline floor ($\text{accuracy} \ge \text{baseline\_acc} - 0.02$)
  And high-confidence error rate MUST not increase.
```

### Scenario 5: Checkpoint Training Summary Records Provenance and Status
```gherkin
Scenario: Training summary artifact records reproducible hyperparameters and commit hash
  Given the completion of the RLCD training pipeline
  When `artifacts/rlcd/rlcd-training-summary.json` is generated
  Then it MUST contain `checkpoint_id`, `goal_id: G-ML-026`, `source_revision`, LoRA hyperparameters, loss history, validation calibration metrics, and safety gate status `APPROVED`.
```
