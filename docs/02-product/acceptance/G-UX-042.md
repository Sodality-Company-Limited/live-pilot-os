## Scenario 1: Shared simulated session

**Expected behavior:** Host and Live Ops see the same session data and can change roles without resetting the scenario.

| Field | Value |
|---|---|
| Input | Start the demo, receive seeded chat events, switch Host ↔ Live Ops. |
| Output | Video, chat, topics, metrics, offer result, and action trace remain consistent. |
| Preconditions | G-UX-041 approved; local app running. |

### Failure cases

| Case | Input | Expected |
|---|---|---|
| Session data unavailable | Simulated feed fails | Show an error/retry state and preserve prior log/metrics. |
| Missing metric | Fixture omits a metric | Display unavailable/unknown, not numeric zero. |

## Scenario 2: Chat, topics, and product signal

**Expected behavior:** The 9:16 stage overlays simulated chat, and repeated or new messages add to a persistent topic log linked to product figures.

| Field | Value |
|---|---|
| Input | Play the approved mock video or select a local video; start slow chat simulation. |
| Output | Chat appears on video; topic entries append; interested viewers, clicks, add-to-cart, price, and stock are visible. |
| Preconditions | Fixture and product mapping approved. |

### Failure cases

| Case | Input | Expected |
|---|---|---|
| Unsupported file | Select a non-video file | Reject it with a readable message; retain demo stage. |
| Repeated question | Multiple same-topic messages | Update the topic count while keeping prior topic entries. |

## Scenario 3: Offer decision and Host cue

**Expected behavior:** Live Ops runs approved deterministic pass/block fixtures; the result and rationale append to the trace and a meaningful outcome updates the Host cue.

| Field | Value |
|---|---|
| Input | Trigger each approved offer fixture. |
| Output | Pass/block status reflects fixture inputs; decision trace remains append-only; Host view shows the corresponding cue. |
| Preconditions | Product-approved fixture values and guardrail behavior. |

### Failure cases

| Case | Input | Expected |
|---|---|---|
| Missing guardrail data | Omit a required margin/stock input | Fail closed; do not show a pass. |
| Duplicate trigger | Trigger the same fixture twice | Each interaction is traceable; no hidden real-world side effect occurs. |

## Scenario 4: Pause, reset, and responsive/accessibility behavior

**Expected behavior:** Pause stops simulated auto-actions, reset requires confirmation and clears demo state, and the UI remains usable across approved viewports.

| Field | Value |
|---|---|
| Input | Pause, attempt an auto-action, reset, then inspect 390px, 768px, and the approved desktop viewport. |
| Output | No action after pause; confirmed reset clears simulated state; keyboard focus, announcements, contrast, and reduced motion follow G-UX-041. |
| Preconditions | G-UX-041 approval includes reference viewport. |
