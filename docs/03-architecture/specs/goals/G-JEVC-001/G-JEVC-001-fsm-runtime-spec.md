## 1. Suggestion Aggregate State Machine

The `Suggestion` aggregate lifecycle models the full lifecycle from LLM inference proposal to terminal host action or expiration.

```text
 ┌──────────────┐
 │   PROPOSED   │ ──(Confidence < SLA OR Stale Facts OR Refused)──► [ WITHDRAWN ]
 └──────┬───────┘
        │
   (Grounding passes &
    Tenant/Session valid)
        │
        ▼
 ┌──────────────┐
 │   GROUNDED   │ ──(Session Paused / Emergency Signal)───────────► [ WITHDRAWN ]
 └──────┬───────┘
        │
   (Transactional Outbox
    Dispatched via NATS)
        │
        ▼
 ┌──────────────┐
 │  DELIVERED   │ ──(Host Accepts & Uses Suggestion)──────────────► [ USED ] (Terminal)
 └──────┬───────┘
        │ ├────────(Host Edits Suggestion Parameters)─────────────► [ EDITED ] (Terminal)
        │ ├────────(Host Dismisses Suggestion)────────────────────► [ DISMISSED ] (Terminal)
        │ ├────────(Clock > freshness_expires_at)─────────────────► [ EXPIRED ] (Terminal)
        │ └────────(Emergency Pause / Retraction Command)─────────► [ WITHDRAWN ] (Terminal)
```

### 1.1. State Definitions

| State | Classification | Description |
|---|---|---|
| `PROPOSED` | Transient | Suggestion payload generated by inference provider, awaiting fact grounding verification. |
| `GROUNDED` | Staged | Passed grounding verification against approved catalog facts; committed to PostgreSQL. |
| `DELIVERED` | Active | Published via NATS JetStream; visible in Host Co-Pilot HUD with active freshness timer. |
| `USED` | Terminal | Host streamer accepted and triggered downstream action (e.g. pinned product, submitted promo proposal). |
| `EDITED` | Terminal | Host streamer adjusted parameters (e.g. customized discount percentage) before triggering action. |
| `DISMISSED` | Terminal | Host streamer manually swiped away or rejected suggestion on the HUD. |
| `EXPIRED` | Terminal | Suggestion was not acted upon before `freshness_expires_at` elapsed; HUD removes suggestion cleanly. |
| `WITHDRAWN` | Terminal | Retracted by system due to emergency pause, session termination, or underlying catalog fact invalidation. |

### 1.2. Transition Guard Matrix

| Source State | Target State | Trigger / Event | Guard Conditions | Actions & Side Effects |
|---|---|---|---|---|
| `[None]` | `PROPOSED` | `InferenceCompleted` | Valid tenant & session; provider outcome = `accepted` | Record `ProviderReceipt`; calculate SHA-256 digests |
| `PROPOSED` | `GROUNDED` | `GroundingVerified` | All catalog facts `fresh`; confidence $\ge$ threshold; no pause | Increment aggregate version; persist to PostgreSQL |
| `PROPOSED` | `WITHDRAWN` | `GroundingFailed` | Any fact stale or unapproved; confidence < threshold | Emits audit receipt; drops suggestion cleanly |
| `GROUNDED` | `DELIVERED` | `OutboxDispatched` | JetStream ACK received from message broker | Publish `copilot.suggestion.created` event |
| `GROUNDED` | `WITHDRAWN` | `EmergencyTriggered` | `control.pause.request` received | Set status `withdrawn`; abort delivery |
| `DELIVERED` | `USED` | `HostAcceptedCommand` | Actor possesses `host.operator` role; session active | Emit audit receipt command; record decision |
| `DELIVERED` | `EDITED` | `HostEditedCommand` | Actor possesses `host.operator` role; payload valid | Emit audit receipt command; record modifications |
| `DELIVERED` | `DISMISSED` | `HostDismissedCommand` | Actor possesses `host.operator` role | Emit audit receipt command; update telemetry |
| `DELIVERED` | `EXPIRED` | `FreshnessTtlElapsed` | Wall-clock time $t > \text{freshness\_expires\_at}$ | Cleanly remove from active HUD projection |
| `DELIVERED` | `WITHDRAWN` | `RetractionCommand` | Emergency pause OR session ended OR catalog updated | Publish `copilot.suggestion.withdrawn` event |

## 2. Provider Invocation Outcomes & Degraded States

Inference provider executions are classified deterministically into 6 discrete outcomes:

```text
       ┌────────────────────────────────────────────────────────┐
       │               Model Provider Invocation                │
       └───────────────────────────┬────────────────────────────┘
                                   │
         ┌─────────────┬───────────┼───────────┬─────────────┐
         ▼             ▼           ▼           ▼             ▼
    [ ACCEPTED ]  [ DEFERRED ] [ REFUSED ] [ TIMEOUT ]  [ CONFLICT / UNKNOWN ]
         │             │           │           │             │
   (Generates    (Payload safe; (Content     (SLA > 2500ms; (Malformed JSON
    Suggestion)   confidence     policy /     circuit open;  or schema error;
                  below SLA)     guardrail)   degraded HUD)  degraded HUD)
```

| Provider Outcome | Guard / Condition | System Behavior | Emitted Event / HUD Impact |
|---|---|---|---|
| `ACCEPTED` | Schema valid, confidence $\ge 7000$ bps, latency $\le 2500$ms | Proceed to grounding and suggestion creation | `copilot.suggestion.created` |
| `DEFERRED` | Output valid but low confidence ($< 7000$ bps) or ambiguous intent | Log provider receipt; no suggestion produced | Silent suppression; HUD maintains stream |
| `REFUSED` | Prompt guardrail violation, safety filter, or refusal payload | Log provider receipt with refusal code; no suggestion | Audit receipt emitted with code `LP05001` |
| `TIMEOUT` | Provider deadline exceeded ($> 2500$ms) or socket error | Abort request; record timeout receipt; increment failure counter | If failures $> 3$, emit `copilot.delivery.degraded` |
| `UNKNOWN` | HTTP 5xx, socket disconnect, or malformed JSON | Record unknown outcome; circuit breaker increments | Fall back to degraded read-only HUD |
| `CONFLICT` | Optimistic locking collision or divergent session revision | Discard stale result; reconcile against current session | Reconcile before next telemetry signal |

### 2.3. Degraded HUD Mode Contract
When provider outages occur (consecutive timeouts or 5xx errors $> 3$), `jev-copilot-service` enters `DEGRADED_MODE`:
1. Publishes `livepilot.v1.copilot.delivery.degraded` with `reason: DEPENDENCY_UNAVAILABLE` and `freshness_sla: STALE`.
2. Core BFF instructs Host UI to render a yellow stale marker and lock guidance creation.
3. Zero synthesized or guessed suggestions are emitted under any circumstances.
