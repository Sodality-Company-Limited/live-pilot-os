## 1. Context & Business Intent

In autonomous AI software systems and multi-agent development environments, human oversight often fails due to two fatal extremes:
1. **Chain-of-Thought (CoT) Cognitive Dump:** Dumping raw, unparsed reasoning traces, sprawling logs, or thousands of tokens of agent internal monologues onto the human operator, inducing alert fatigue, cognitive overload, and rubber-stamping approvals.
2. **Opaque Black-Box Approvals:** Presenting generic, unverifiable summaries lacking direct cryptographic links to disk artifacts, visual pixel diffs, AST mutations, or quantitative proof receipts.

Goal `G-WEB-011` resolves this by codifying an operational Human-in-the-Loop (HITL) review system for Soda OS under DAVE governance that guarantees:
- **Zero CoT Opacity:** Review packets present high-signal, compact decision summaries without raw LLM internal monologues, focusing strictly on: Goal Touch Map, Calibrated Confidence, Risk Tier, Multi-Expert Consensus/Conflict, and Quantitative Proof Receipts.
- **Audit Ledger Aggregation:** The review engine dynamically scans `.agents/audit/decisions.jsonl`, `docs/07-backlog/evidence/`, and `artifacts/proofs/` to aggregate genuine verified decisions and proof receipts without relying on hardcoded stubs or dummy fallback objects.
- **Deterministic CLI Commands:** Provides `soda dave show-review-packet <goalId>` to format and persist `artifacts/review/DAVE-REVIEW-PACKET.md`, and `soda dave review <goalId> <status> --note <note>` to record immutable operator decisions with SHA-256 digests into `.agents/audit/decisions.jsonl`.
- **Constitutional Zero-Mock Invariant:** All aggregation, verification, formatting, and file I/O operations are 100% concrete, fail-closed on corrupt or missing records, and thoroughly verified by automated test harnesses.

3. **Format Determinism:** Resolved by standardizing the 5-section packet structure: Header & Status, Executive Summary, Touched Components & Mutated Artifacts, Proof Receipts & Empirical Metrics, and Actionable Approval Triggers.

## 4. Multi-Choice Architectural Decision Ledger

### Question 1: How should review packets aggregate data across multiple goal decisions?
- **Option A:** Read only the last written line in `.agents/audit/decisions.jsonl`. *(Rejected: incomplete, ignores multi-expert decisions and external proof receipts)*.
- **Option B (Recommended):** Aggregate all verified decisions matching `goalId`, parse accompanying proof receipts in `docs/07-backlog/evidence/` and `artifacts/proofs/`, and compute aggregated confidence and risk tiers. *(Holistic, audit-compliant, robust)*.

### Question 2: How should missing goals or unrecorded decisions be handled by CLI commands?
- **Option A:** Fall back to a dummy placeholder decision so the command does not crash. *(Strictly prohibited by Article I: Zero Mocks, Zero Fallbacks)*.
- **Option B (Recommended):** Fail-closed with exit code 1, emitting clear diagnostic messages indicating that no verified decisions exist for the specified goal. *(Zero fallbacks, production-safe, secure)*.

### Question 3: Where should generated review packets be persisted on disk?
- **Option A:** Log solely to standard output (stdout). *(Ephemeral, untracked by filesystem audits)*.
- **Option B (Recommended):** Output to stdout AND write to `artifacts/review/DAVE-REVIEW-PACKET.md` with SHA-256 digest computation for non-repudiation. *(Permanent, versionable, inspectable)*.
