# G-UX-042 — Socratic 5-Why Problem Analysis

> Source-cited working analysis, not validated customer research. Derived from P-001/E-001 and G-UX-041.

1. **Why build the UI?** The Hackathon team needs a coherent browser demo of the agreed Live OS workflow.
2. **Why is a coherent demo needed?** Host and Live Ops need to see how one chat signal leads to a topic/product signal, offer decision, and Host cue.
3. **Why show both roles together?** The value depends on shared session context rather than isolated screens.
4. **Why use a simulated session?** The current Hackathon project has no approved real platform connection; the source design explicitly requires mock video/chat for the pitch.
5. **Why define the boundary?** A demo must communicate the product flow without implying live marketplace actions or validated production policy.
