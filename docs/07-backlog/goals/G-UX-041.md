## Context

Live OS is a hackathon live-commerce demo with separate Host and Live Ops views over one simulated session. This goal records its UX flow, states, UI specification, and product-scoped token proposal before implementation.

## Intent

**Why:** Host and Live Ops lack one shared view of audience questions, product interest, and offer checks during a live session ([P-001](../../02-product/knowledge-map.json), based on [E-001](../../02-product/knowledge-map.json)).<br>
**Done when:** The role views, shared demo flow, five screen states, responsive behavior, accessible UI specification, and single-theme token proposal are documented and approved by Product/Design.<br>
**Unblocks:** A later UI implementation goal after design approval.

## How

Produce design artifacts only. Keep CSS variables as the Live OS token source; retain the global Soda OS token contract and wait for Product/Design approval before UI implementation.

## 🏛️ Comprehensive Spec Design Appendix

### Finite State Machine (FSM) Matrix

| Current | Trigger | Guard | Next | UX response |
|---|---|---|---|---|
| Empty | Start scenario | Scenario available | Loading | Announce preparation and preserve layout. |
| Loading | Feed ready | Session payload valid | Success | Show video/chat and append incoming topics. |
| Loading | Feed failure | — | Error | Explain retry; preserve prior history. |
| Success | Source unavailable | Required data incomplete | Partial | Label missing data; block unsafe offer approval. |
| Any active state | Reset | User confirms | Empty | Clear simulated feed, topics, metrics, and decision trace. |

### Mathematical & Data Invariants Spec

- This design goal introduces no business calculation algorithm.
- Missing product values remain distinguishable from numeric zero.
- Price/discount/margin are display-only simulated inputs; a missing required guardrail input cannot produce a pass result.

### Hexagonal Inbound & Outbound Ports

- No application ports, adapters, APIs, or persistence are implemented in this design goal.
- The later implementation goal must define the session-state contract and real platform boundaries before adding integrations.
