### Worktree & Multi-Subagent Orchestration Plan

Use one goal-scoped worktree and one owner. UI state and shared session behavior are tightly coupled; parallel edits would create unnecessary coordination. See [worktree plan](../../03-architecture/specs/goals/G-UX-042/G-UX-042-worktree-plan.md).

## Context

G-UX-041 defines the Host and Live Ops information architecture, shared simulated-session flow, UI states, and warm dark token proposal. This goal implements that approved design as a browser UI; the repository currently has a standalone HTML demo and tokens but no Next.js app scaffold.

## Intent

**Why:** The team needs a presentable, interactive demo that makes the agreed Host/Live Ops workflow visible and reviewable.<br>
**Done when:** A browser UI renders both role views from one shared simulated session, demonstrates the audience/topic/product and offer-decision flow, and passes the acceptance checks below.<br>
**Unblocks:** Hackathon rehearsal and later backend/platform integration goals.

## In

- Create the Next.js UI scaffold in the repository using the latest stable version at implementation time and the project-approved Motion for React dependency.
- Implement separate Host and Live Ops views backed by the same in-memory simulated session.
- Show the 9:16 video stage with overlaid mock chat; support local video selection for the demo.
- Keep audience topics in a persistent log and show product interest, clicks, add-to-cart, price, and stock.
- Provide Host cues, offer pass/block results, an append-only decision trace, pause/reset controls, and explicit simulated labels.
- Apply the single warm dark theme and semantic variables in `src/tokens.css`.
- Meet the responsive, keyboard, screen-reader, and reduced-motion requirements in G-UX-041.

## Out

- Live marketplace/video/chat APIs, authentication, persistence, real offer execution, and real inventory reservations.
- Reworking the approved IA, UI component contract, or token palette; changes require design approval and an updated G-UX-041 artifact.
- Production deployment, business policy decisions, or new product capabilities not traced to the Requirements Baseline.

## Atomicity & Zero-Mock Contract

- **One outcome:** A reviewable, interactive UI for the Host and Live Ops views over one shared demo session.
- **Concrete execution:** Build the browser application and deterministic demo flow; simulated inputs are intentional product fixtures and must be labeled; do not use a dummy pass response to claim a live result.
- **Simulation boundary:** Mock chat, catalog, video, and offer outcomes are intentional demo inputs; visibly label them as simulated. Do not represent them as platform responses or production proof.
- **No external side effects:** This goal makes no live platform calls and changes no real offers or inventory.
- **Security boundary:** Local video remains in the browser session; never upload it or persist it in this goal.

### Antigravity handoff contract

When this goal is handed to Antigravity, review only the goal and its linked UX/UI/token artifacts. Do not change scope, mark design approved, or introduce real integrations without an explicit product decision.

## Acceptance criteria

- [ ] Host and Live Ops are distinct views of the same session; switching roles preserves current video, chat, topic history, product figures, and action trace.
- [ ] The portrait stage is 9:16, supports a local video file, overlays simulated chat, and displays a clear simulation label.
- [ ] New chat/topic entries append to a persistent log; they do not replace prior entries. Product signals show interested viewers, clicks, add-to-cart, price, and stock, with missing values distinct from zero.
- [ ] Live Ops can run the approved deterministic offer scenarios; each outcome is explained and appended to the decision trace. Relevant outcomes update the Host cue.
- [ ] Pause prevents further simulated auto-actions; reset clears the scenario only after the specified confirmation.
- [ ] One warm dark theme is used through semantic tokens; no light-theme switch or raw component palette is added.
- [ ] At the approved desktop reference viewport the page fits without document scrolling; narrower layouts reflow per G-UX-041.
- [ ] Keyboard focus, screen-reader announcements, contrast, reduced motion, and invalid local-video input meet the UI specification.
- [ ] `npm run build` and `node scripts/ui-smoke/live-os-demo.mjs` pass; manual checks at the approved viewport sizes are recorded.
- [ ] No real platform call, uploaded video, real voucher, or inventory mutation occurs.

## Test plan

- **Build:** `npm run build` after the app scaffold defines the script.
- **Browser smoke:** `node scripts/ui-smoke/live-os-demo.mjs` against the local Next.js app.
- **Positive:** Start scenario, receive multiple chat events, view persistent topics/product signals, pass the approved offer fixture, and see the Host cue update.
- **Negative:** Block the below-floor fixture; reject invalid video type; missing guardrail data must not display a pass.
- **State/accessibility:** Switch roles without losing session state; pause stops generated events; reset clears only after confirmation; keyboard and reduced-motion checks pass.
- **Responsive review:** 390px, 768px, and approved desktop viewport; capture review evidence.
- **Security boundary:** Inspect network activity to confirm the local video is not uploaded and no marketplace endpoint is called.
