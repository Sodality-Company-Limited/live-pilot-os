## Context

Current language model training optimizes for binary correctness, encouraging overconfident hallucinations in autonomous agent workflows. This goal implements the RLCD loss objective that severely penalizes confident wrong decisions.

## Intent

**Why:** Autonomous agents must exhibit calibrated uncertainty so that external governance can reliably route uncertain decisions to automated verification or human review.

**Done when:** A PyTorch loss module computes logarithmic scoring, quadratic overconfidence penalties, and evidence penalties with verifiable numerical stability and monotonic derivatives.

**Unblocks:** Parameter-efficient LoRA training pipeline (G-ML-007).

## 1. Problem and Value

- **Problem:** Absence of calibrated uncertainty estimation and reproducible ML guarantees in Soda OS agent execution.
- **Affected users or agents:** Autonomous agents making high-stakes tool execution and code generation decisions.
- **Current behavior:** Agents treat all model outputs with uncalibrated certainty, causing high-confidence errors and unverified deployments.
- **Failure cost:** Catastrophic failure in production due to silent hallucination and unmitigated risk actions.
- **Desired behavior:** Mathematical loss class combining logarithmic scoring, Brier regularization, and asymmetric overconfidence penalties.
- **Why now:** Foundation requirement for production-grade agent reliability and formal verification.
- **If not completed:** System remains vulnerable to distribution shift, overconfidence, and silent execution corruption.

## Work steps

### Step 1 — Implement proper scoring and penalty functions

**Allowed files:** `code/ml/src/training/losses/calibrated_reward.py`  
**Actions:**
1. Create CalibratedRewardLoss class inheriting from torch.nn.Module.
2. Implement forward method computing log loss, quadratic overconfidence penalty, and evidence scaling.

**Verification command:** `pytest tests/ml/test_calibrated_loss.py -k test_loss_forward`  
**Completion gate:** Loss computes forward pass with finite float32 outputs.  
**Stop condition:** Loss produces NaN or Inf values on boundary inputs (c in {0.0, 1.0}).  
**Zero-Mock invariant check:** 100% operational PyTorch tensor math; zero mocked tensor returns.

### Step 2 — Verify monotonicity and asymmetric penalty scaling

**Allowed files:** `tests/ml/test_calibrated_loss.py`  
**Actions:**
1. Write unit tests checking that loss monotonically increases for incorrect answers as confidence approaches 1.0.
2. Assert that incorrect loss at c = 0.95 is at least 5x higher than at c = 0.20.

**Verification command:** `pytest tests/ml/test_calibrated_loss.py -k test_asymmetric_penalty`  
**Completion gate:** All mathematical assertions pass with terminal exit code 0.  
**Stop condition:** Overconfidence penalty ratio is less than 5x.  
**Zero-Mock invariant check:** Concrete tensor assertions on real gradient vectors.

### Step 3 — Verify backward pass autograd stability

**Allowed files:** `tests/ml/test_calibrated_loss.py`  
**Actions:**
1. Execute backward pass checking that parameter gradients are finite and non-zero.
2. Run gradient check (torch.autograd.gradcheck) against double precision tensors.

**Verification command:** `pytest tests/ml/test_calibrated_loss.py -k test_autograd_stability`  
**Completion gate:** torch.autograd.gradcheck returns True with exit code 0.  
**Stop condition:** Gradient discrepancy or non-finite gradient detected.  
**Zero-Mock invariant check:** Real PyTorch automatic differentiation; zero mocked gradient objects.
