## Context

Continuous confidence estimates must translate into optimal discrete agent actions (proceed, verify, defer, human_review) according to domain-specific risk matrices.

## Intent

**Why:** Translates continuous confidence scores into discrete agent action policies that trigger safety protocols rather than silent failures.

**Done when:** A threshold optimizer produces policy parameter configurations that bound high-risk false acceptances below 1% and false deferrals below 5%.

**Unblocks:** Adversarial red-teaming safety suite (G-ML-011).

## 1. Problem and Value

- **Problem:** Absence of calibrated uncertainty estimation and reproducible ML guarantees in Soda OS agent execution.
- **Affected users or agents:** Autonomous agents making high-stakes tool execution and code generation decisions.
- **Current behavior:** Agents treat all model outputs with uncalibrated certainty, causing high-confidence errors and unverified deployments.
- **Failure cost:** Catastrophic failure in production due to silent hallucination and unmitigated risk actions.
- **Desired behavior:** Decision policy optimization module that trains routing tokens or tunes threshold boundaries mapping predicted confidence into discrete action policies.
- **Why now:** Foundation requirement for production-grade agent reliability and formal verification.
- **If not completed:** System remains vulnerable to distribution shift, overconfidence, and silent execution corruption.

## Work steps

### Step 1 — Implement cost-sensitive empirical risk loss function

**Allowed files:** `code/ml/src/training/defer_policy.py`  
**Actions:**
1. Create DeferPolicyOptimizer defining asymmetric penalties for false accepts versus false deferrals.
2. Implement evaluation function computing expected loss given a set of routing thresholds tau_low and tau_high.

**Verification command:** `pytest tests/ml/test_defer_policy.py -k test_cost_function`  
**Completion gate:** Cost function penalizes confident incorrect decisions 10x higher than deferral costs.  
**Stop condition:** Cost function returns negative values or inverts risk penalties.  
**Zero-Mock invariant check:** Real analytical risk formulation; zero mock loss scores.

### Step 2 — Optimize threshold boundaries on validation split

**Allowed files:** `code/ml/src/training/defer_policy.py, code/ml/configs/policy_thresholds.yaml`  
**Actions:**
1. Run grid optimization across 500 labeled validation decisions to identify Pareto-optimal routing thresholds.
2. Save calibrated thresholds to code/ml/configs/policy_thresholds.yaml.

**Verification command:** `pytest tests/ml/test_defer_policy.py -k test_threshold_optimization`  
**Completion gate:** Thresholds satisfy tau_low < tau_high with false accept rate < 1.0%.  
**Stop condition:** Threshold boundaries fail safety constraints or tau_low >= tau_high.  
**Zero-Mock invariant check:** Mathematical optimization over real validation data; zero placeholder thresholds.

### Step 3 — Validate policy confusion matrix and boundary cases

**Allowed files:** `tests/ml/test_defer_policy.py`  
**Actions:**
1. Evaluate policy performance across 100 edge-case test decisions.
2. Assert that 100% of high-risk decisions with confidence below tau_high are routed to defer or verify.

**Verification command:** `pytest tests/ml/test_defer_policy.py -k test_policy_bounds`  
**Completion gate:** Policy passes 100% of safety test cases with exit code 0.  
**Stop condition:** Any high-risk decision incorrectly routed to proceed.  
**Zero-Mock invariant check:** Concrete evaluation against deterministic test fixtures; zero simulated outputs.

### 5. Proof-and-Evidence Contract & Epistemic Taxonomy

Every capability claim MUST be categorized according to the **5-Gate Epistemic Taxonomy**:
- **Gate 1: Executable Invariant** — In-kernel assertions, state-machine transitions, runtime bounds, property tests.
- **Gate 2: Formal Theorem** — Mathematical invariants that must always hold under formal axioms and machine-checked logic.
- **Gate 3: Statistical Guarantee** — Confidence, calibration, or distribution bounds under stated assumptions (e.g. Brier score $le 0.08$, ECE $le 0.04$, Wilson score intervals).
- **Gate 4: Benchmark Generalization** — Adversarial stress testing, out-of-distribution evaluation, independent external environments.
- **Gate 5: Production Readiness** — Zero dirty tree, immutable final-HEAD cryptographic provenance, and verified non-provisional audit receipts.

$$\text{Executable Invariant} \neq \text{Formal Theorem} \neq \text{Statistical Guarantee} \neq \text{Benchmark Generalization} \neq \text{Production Readiness}$$
