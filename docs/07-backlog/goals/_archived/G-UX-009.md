## Context

Standardizing visual UI element labeling across training and verification pipelines requires a formal taxonomy. Elements must be categorized with precision, defining allowed interaction states, required ARIA roles, and WCAG 2.2 AAA touch target criteria.

## Intent

Standardize and formalize the 32-element component hierarchy, functional categories, interaction states, and accessibility constraints into an authoritative specification.

**Why:** Machine learning pipelines require an unambiguous ground-truth component taxonomy to train vision adapters, scene graph generators, and evaluation harnesses without semantic drift.  
**Done when:** Taxonomy schema, JS/Python libraries, unit tests, and verification harness pass with exit code 0.  
**Unblocks:** G-UX-010 (Stage 2 UI Scene Graph Pairs Dataset).

## How

Define `schemas/ui-taxonomy.schema.json` under JSON Schema Draft 2020-12. Implement `scripts/lib/ui-taxonomy.mjs` and `code/ml/src/curriculum/taxonomy.py` declaring the 32 classes across 6 categories (8 containers, 7 controls, 6 inputs, 5 display, 3 data/feedback, 3 navigation). Implement element validation enforcing allowed states, valid ARIA roles, and WCAG 2.2 AAA minimum 44x44px touch targets. Test with `tests/unit/test-ui-taxonomy.mjs`, `tests/ml/test_curriculum_taxonomy.py`, and `scripts/harness/ui-taxonomy-harness.mjs`.
