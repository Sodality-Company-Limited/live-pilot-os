## Context

In regulated and high-assurance environments, models cannot be deployed without complete, immutable traceability back to training data, hyperparameters, source code revisions, and evaluation metrics. Cryptographic model provenance guarantees non-repudiation and tamper detection across the entire model lifecycle.

## Intent

Record cryptographic proofs of model weights, training lineage, evaluation metrics, and dataset revisions in an immutable HMAC-signed ledger.

**Why:** Autonomous systems demand verifiable audit trails ensuring weights originate from verified curriculum datasets and satisfy calibrated performance bounds.  
**Done when:** Model provenance schema is codified, PyTorch tracker computes SHA-256 digests and manifests, Node.js ledger chains blocks with HMAC-SHA256 signatures, dataset lineage tracks Stages 1-6, and tamper detection is verified.  
**Unblocks:** G-UX-020 (Autonomous UI Auditing), G-UX-021 (UX Expert Agreement Benchmark).

## How

Define JSON Schema in `schemas/model-provenance.schema.json`. Implement PyTorch provenance tracking module in `code/ml/src/training/provenance_tracker.py` and Node.js tamper-evident ledger in `scripts/lib/model-provenance-ledger.mjs`. Bind physical SHA-256 byte hashes for training curriculum stages 1 through 6 (`artifacts/curriculum/`). Record base checkpoint, adapter SHA-256 digests, hyperparameters, active git commit SHA, and calibration metrics (ECE, Brier, AUROC, win rate). Enforce blockchain-style hash chaining (`previous_block_hash`) and HMAC-SHA256 signatures. Verify with unit tests and `scripts/harness/model-provenance-ledger-harness.mjs`.

## 5-Tier Test Suite Specification

### 1. Positive Tests
- Ledger links blocks into an unbroken chain verified with cryptographic HMAC-SHA256 signatures.
- Stage 1 through 6 dataset hashes match physical files in `artifacts/curriculum/`.

### 2. Negative Tests
- Tampering with any byte in past blocks causes verification failure immediately.
- Rejection of manifests missing required cryptographic fields.

### 3. Fail-Closed & Chaos Tests
- Corrupt signature key halts verification fail-closed.
- Missing dataset referenced in lineage fails validation without silent fallback.

### 4. Temporal Causality Tests
- Monotonically increasing block indices and deterministic UTC RFC 3339 timestamps.

### 5. Security & Air-Gap Checks
- Air-gapped local execution without external network telemetry calls.
- Secret HMAC signing keys remain local and never committed in plaintext.
