## Context

Audit logs in autonomous AI platforms must provide mathematical non-repudiation and tamper-evident guarantees for SOC 2 Type II and ISO 27001 compliance. Modifying, deleting, or reordering any historical design decision record must immediately invalidate all subsequent block hashes and the Merkle root fail-closed. Furthermore, physical evidence files on disk must be cryptographically probed and bound to ledger blocks.

## Intent

Implements append-only JSONL persistence with SHA-256 block hash chaining and binary Merkle tree root verification.

**Why:** Guarantees cryptographic non-repudiation and immutable evidence trails for all UX decisions and stage-gate approvals.  
**Done when:** Ledger appends decisions into append-only JSONL, computes binary Merkle roots and inclusion proofs, detects data tampering fail-closed, and verifies physical disk evidence.  
**Unblocks:** Immutable compliance auditability across Soda OS.

## How

Implement `scripts/lib/merkle-decision-ledger.mjs` providing `MerkleDecisionLedger`, `computeMerkleRoot`, `generateMerkleProof`, `verifyMerkleProof`, and `probeEvidenceFiles`. Chain each block to the previous block hash via `prev_hash` (with genesis block `0000...0000`). Compute deterministic canonical block hashes over index, timestamp, decision ID, sorted payload hash, previous hash, nonce, and evidence root. Implement `verifyIntegrity` checking sequence continuity, hash chaining, and block integrity, throwing `LedgerCorruptionError` on any tampering. Verify via unit tests in `tests/unit/test-merkle-decision-ledger.mjs` and domain harness `scripts/harness/merkle-decision-ledger-harness.mjs`.
